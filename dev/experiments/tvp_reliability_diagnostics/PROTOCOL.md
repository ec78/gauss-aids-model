# TVP-AIDS Phase D0: reliability-diagnostic feasibility

Status: **FROZEN v1 before analysis**. This is a dev-only retrospective
study. It changes no shipped source, public API, package metadata, examples,
or user documentation.

## Question

Which warnings about a fitted TVP-AIDS `Q` can be supported honestly by the
evidence already produced in Phases C and Q0, and which require another fit or
private objective calculations?

This phase does not design inference for variance components, claim that `Q`
is identified, or change the meaning of `mleRetcode`.

## Frozen evidence

All inputs are committed at parent `0b1d9c2`:

- `dev/experiments/tvp_conv_study/results/categories.csv`;
- `dev/experiments/tvp_q_identification/results/endpoint_summary.csv`;
- `dev/experiments/tvp_q_identification/results/fits.csv`;

The five Q0 endpoints are the complete retrospective set: four known-truth

`n1=3`, `tobs=500` example-data anchor with static `H`. No new GAUSS fit or
new seed is permitted in D0.

## Diagnostic layers

The analysis must keep computation costs visible:

1. **One public fit.** `quaidsTVPOut` exposes `mleRetcode`, `q0`, `Qfit`, the
   state paths/covariances, and `bFinal`. Therefore a caller can check the
   return code, finiteness/positivity, and start-relative `Qfit/q0` scale.
   It cannot obtain the objective value, gradient, Hessian, iteration count,
   or an endpoint-comparison result from this struct.
2. **Extra starts.** Endpoint agreement needs at least two additional fits
   plus an objective evaluation on a common total-log-likelihood scale. D0
   uses Q0's three starts (0.1x, 1x, 10x shipped start). An endpoint is
   `START-STABLE-OBSERVED` only when all three return code 0, the maximum LL
   gap is at most `tol = 1e-6 * nobs`. Q-vector differences are reported but
   do not gate the label: equivalent-likelihood endpoints can differ along a
   flat boundary ridge. This is a reproducibility label for the starts tried,
   not a global-optimum proof.
3. **Private objective work.** Boundary count, all-floor loss, local log-Q
   Hessian, condition number, and profile results come from Q0's private
   harness. They are not currently available from one public
   `quaidsTVPFit()` result.

## Frozen warning semantics

The output is descriptive and uses these labels in precedence order:

- `FIT-FAILED`: any start has nonzero `mleRetcode`.
- `START-SENSITIVE`: the extra-start rule above fails.
- `GEOMETRY-CAUTION`: starts agree, but any of the following holds: at least
  one boundary element (`Qfit < 1e-3 qRef` under Q0's endpoint-specific
  reference), at least one flat Hessian direction (`eig(-H) < 1e-3`), or at
  least one element has floor loss below the 1.92 descriptive marker.
- `NO-CAUTION-OBSERVED`: none of those conditions was observed.

`GEOMETRY-CAUTION` is not an error and must not be paraphrased as failed
identification. `NO-CAUTION-OBSERVED` is not proof of identification. The
0.1 and 1.92 LL markers and the boundary/Hessian thresholds are inherited
unchanged from frozen Q0; they are not tests and have no regular chi-square
interpretation at a variance boundary.

The analysis also reports `loss_floor_all`, the step-0.01 interior Hessian
condition number when an interior block exists, and the number of boundary
and flat directions. These values explain a caution but do not alter its
precedence.

The transformed maximum gradient is summarized only as an availability gap,
with no warning threshold: the square-root-Q transform mechanically drives
the transformed score toward zero at a variance boundary. There is no
fixed-point residual in the current implementation. A missing CMLMT
covariance/inversion warning could support a caution in a future internal
result, but Q standard errors remain unsupported and the public output does
not expose that status.

## Outputs and gates

`analyze_d0.py` uses only Python's standard library and writes:

- `results/diagnostics.csv`, one row per endpoint;
- `RESULTS.md`, the feasibility matrix, endpoint table, findings, and limits.

`test_analyze_d0.py` exercises every classification branch and the inclusive
LL tolerance boundary without reading study results.

The analysis passes only if all four input schemas are present, endpoint sets
match exactly where applicable, there are five endpoints, every endpoint has
exactly three Q0 fits, and the output can be regenerated byte-for-byte.

After this protocol and analyzer are committed, running the analyzer is the
measurement boundary. Results are committed separately. No push, merge,
public API proposal, source edit, or broad sweep is authorized by this phase.

## Candidate decision after D0

D0 may recommend a later public design, but cannot implement it. The default
shape to assess is a separate diagnostic result/procedure rather than adding
inferential meaning to `quaidsTVPOut`: a cheap single-fit status/scale layer,
an opt-in multi-start layer, and explicitly advanced/private geometry work.
